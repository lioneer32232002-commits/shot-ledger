## 二、為什麼是「加到主畫面」而不是別的

Safari 對**沒有加到主畫面**的網站有 script-writable storage 的 7 天上限，閒置就可能
整份 localStorage 被清掉；已安裝的 PWA 不受此限。而 `navigator.storage.persist()`
Safari 沒有實作 → 設定頁原本那行「儲存空間已受保護」在 iOS 永遠不會出現。

⚠️ **使用者沒有 iOS 裝置，這件事本質上也無法實測**（要等 7 天且期間完全不互動）。
所以 §4 的設計原則是「不靠偵測、不靠平台判斷」：`env.js` 的 UA 判斷只用來決定
**講哪一句安裝步驟**，不用來決定要不要顯示引導。判斷錯的最壞情況是文案不精確，
不會有人看不到卡片。可以在任何瀏覽器驗證的是「資料真的被清掉之後 App 不會壞」——
手動清 localStorage 重開，確認進得去、匯入入口找得到。

已做完的 iOS 靜態稽核（`SPEC_M14` §0）：`100dvh`／`env(safe-area-inset-*)`／
日期全走 ISO 字串／canvas 1080×1350 遠低於 iOS 面積上限，四項都乾淨。

   （本包沒動這三者，仍照規矩跑過一次）。
3. push main 後 `gh run watch` 綠燈。
4. 最終以線上為準：抓 `https://shot-ledger.pages.dev/sw.js` 驗 `CACHE_NAME`
   （本次應為 `shotledger-v35`）。
5. 兩台機器共推 main：改 schema／SW 版號前必先 `git fetch`（本次已做）。
6. **本機驗證陷阱（本次新增一條，很重要）**：SW 改成 cache-first 之後，
   改完程式重新載入**會吃到舊的 js／css**。本機驗證前務必先
   `navigator.serviceWorker.getRegistrations()` 全部 unregister ＋ `caches.delete()`
   再 reload，否則會對著舊程式除錯。
7. 另一個本機陷阱：本環境的瀏覽器分頁**不 compositing frames**，所以截圖工具逾時、
   **CSS transition 會永遠停在 `state=running`**（computed style 讀到的是起始值）。
   要驗 transition 的終態就把 `style.transition='none'` ＋ `getAnimations().finish()`
   之後再讀。本次的 `<details>` 箭頭旋轉就是這樣驗的。
