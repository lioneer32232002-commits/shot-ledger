# SPEC_M18 — 飽和色塊上的文字：全站對比度修正（2026-07-30）

> 承 `SPEC_M17` §6 的待辦：`--color-accent` ＋白字在兩個主題都低於 AA。
> 使用者決定「全站按鈕對比度可以改」。

## 1. 根因不是某顆按鈕，是一個模式

實測（淺色／深色雙主題）：

| 組合 | 修正前 | AA 小字需求 |
|---|---|---|
| accent 底 ＋ 白字（主要鈕、選中態、SHOT 圓鈕…） | 3.58（淺）／3.08（深） | 4.5 |
| success 底 ＋ 白字（階梯磁磚的 ✓） | 5.07（淺）／**2.0**（深） | 4.5 |
| danger 底 ＋ 白字（清除資料鈕） | 5.5（淺）／**2.9**（深） | 4.5 |
| danger 當文字（描邊危險鈕） | 5.9（淺）／**3.2**（深） | 4.5 |

深色模式特別慘的原因很單純：暗底需要**亮**的飽和色（亮橘／亮綠／亮紅才看得出是那個
語意色），而亮色配白字必然沒有對比。所以這不是調某顆按鈕的顏色，是「文字壓在飽和
色塊上」這個模式本身要有規則。

## 2. 做法：兩顆新 token，兩個主題各自正解

```
:root                      --color-fill-accent: #B8430A;  --color-on-fill: #FFFFFF;
:root[data-theme="dark"]   --color-fill-accent: #F2691D;  --color-on-fill: #16130F;
```

- **淺色模式**：色塊壓深一階（accent → accent-dark 那一階），文字維持白。
- **深色模式**：色塊維持亮橘（暗底需要亮 accent），文字改近黑。

兩個主題的正解本來就不同，不要為了「一致」硬用同一組。`--color-accent` 本身**不動**
（它還是品牌色，用在文字、邊框、進度條、pip 等不承載文字的地方）。

另外新增 `--color-danger-text`（淺 #B23B2E／深 #F09A8F）：深色模式的 `--color-danger`
是給色塊用的亮紅，拿來當文字只有 3.2。**填色不變，只有文字走這顆。**

`--color-text-on-accent` 與 `--color-accent-contrast` 標記 `@deprecated`（已無人使用，
留著避免有人以為被誤刪）。

## 3. 套用範圍（13 條規則 ＋ 故事頁 CTA）

主要鈕／次要選中態／chip 選中／分段控制選中／SHOT 圓鈕／快速輸入模式鈕／
數字鍵盤選中與按下態／實投數選中／逐球球圖已進／連莊生涯新高徽章／階梯磁磚 ✓／
填色危險鈕／描邊危險鈕／`story.css` 的 `.cta`。

純色塊（`curve-bar__fill`、熱力格、週目標進度條、連莊 pip、`::before` 標記）沒有文字，
**不在此規範內、維持原色**——它們的亮度是資訊本身，改了反而讀不出強弱。

## 4. 驗收（2026-07-30，逐元素量測、雙主題）

| 控制項 | 淺色 | 深色 |
|---|---|---|
| 主要鈕 | 5.46 | 6.01 |
| 次要鈕（描邊） | 5.46 | 4.77 |
| 填色危險鈕 | 5.90 | 5.73 |
| 描邊危險鈕 | 5.61 | 8.57 |
| 低調鈕 | 5.83 | 7.82 |
| 分段控制（選中／未選） | 5.46／5.35 | 4.77／6.47 |
| 色塊 vs 頁底（非文字需 3.0） | 5.19 | 6.01 |

⚠️ **本環境量測陷阱（第三次踩到，務必記住）**：這個瀏覽器分頁不 compositing frames，
所以 **CSS transition 永遠停在起始值**。`.btn` 有 `transition: background`，用 JS 切
`data-theme` 之後直接讀 computed style，會讀到「切換前的底色 ＋ 切換後的文字色」，
量出一堆假的失敗（主要鈕一度量到 3.39）。**量測前先注入
`*{transition:none!important;animation:none!important}`**；頁面淡入的 `.page` 也會
卡在 `opacity:0`，同樣要在探針裡強制 `opacity:1`。

## 5. 未處理：faint／muted 小字（需要使用者決定，不在本包範圍）

同一次掃描發現一個**更大**的問題：`--color-text-faint` 用在很多承載資訊的小字上——
`section-title`、`ladder-tile__name`、`badge-medal__name/meta`、`heat-cal__month`、
`lifetime-card__label`、`stats-empty-note`、`badge-strip__meta`、`about-card__note`、
`settings-card__title` 等，實測 **2.99〜4.4**，全數低於 AA 4.5。

為什麼不順手改掉：淺色底要讓小字達到 4.5，faint 必須壓深到幾乎等於 muted
（計算：底色 #FAF9F7 要 4.5:1，文字亮度上限 ≈ muted 的亮度）——等於**灰階三階
（text / muted / faint）被壓成兩階**，全站的輕重層次會整個變重。那是視覺系統的取捨，
不是修 bug，應該由使用者決定，可能還要比稿。

三個可能方向（留給下一次討論）：
1. **收掉 faint**：faint → muted，接受畫面變重，換全站 AA。
2. **限縮 faint 的用途**：只准用在純裝飾（刊號浮水印、pip、分隔符），凡是承載資訊的
   標籤一律 muted 起跳。這是我建議的方向，改動集中在十來個 class。
3. **維持現狀**：AA 不是法規要求，小字用淺灰是這個 App 的調性之一。

（`page-banner__*` 量到 1.05 是**假警報**：白字壓在照片橫幅上，色值算不出真實對比，
掃描器無法評估照片底，那幾處視覺上有 scrim 是清楚的。）
